# Запуск Civilist за 0 ₽

GitHub хранит код и историю изменений. Cloudflare Workers запускает приложение, а D1 хранит материалы и учебный прогресс. Используй тариф **Free** и бесплатный адрес `*.workers.dev`; собственный домен для первого запуска не нужен.

Сначала создаём рабочую версию вручную, затем подключаем обновления из GitHub. Существующий сайт на Sites работает отдельно до завершения переноса.

Для отдельного тестового сайта используй [QA.md](QA.md): там описаны `civilist-qa`, база `civilist-db-qa` и команды с суффиксом `:qa`. Проверки PR и доставку выбранной ветки кнопкой GitHub подключаем по [CI_CD.md](CI_CD.md) после проверки разделения основного и тестового окружений.

## 1. Подготовь аккаунт и компьютер

1. Создай аккаунт на https://dash.cloudflare.com/sign-up и подтверди почту.
2. Установи Node.js 24 LTS и Git. Проверь в терминале: `node --version`, `npm --version`, `git --version`.
3. Скачай проект:

```bash
git clone https://github.com/Pandasayok/civilist.git
cd civilist
npm ci
```

Если репозиторий уже скачан, открой его папку и выполни `git pull`, затем `npm ci`.

## 2. Создай базу D1

```bash
npx wrangler login
npm run db:create
```

`wrangler login` откроет браузер для входа в Cloudflare. После создания `civilist-db` команда выведет `database_id` — UUID вида `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`. Подставь свой UUID:

```bash
npm run db:configure -- ТВОЙ_DATABASE_ID
```

Вместо команды базу можно создать в панели Cloudflare: **Storage & databases → D1 → Create database**, имя `civilist-db`. Скопируй её Database ID и выполни ту же команду настройки.

Database ID можно сохранить в GitHub: это идентификатор базы, а не пароль. В репозитории первоначально стоит заглушка, поэтому запуск в интернете блокируется, пока реальная база не настроена.

## 3. Создай закрытый доступ

```bash
npm run access:create
```

Команда создаст два локальных файла:

- `.civilist-access.txt` — отдельный код администратора и код Софьи. Сохрани их в менеджере паролей. Код Софьи используется на всех её устройствах.
- `.civilist-secrets.json` — настройки для Cloudflare. В них хранятся только хеши кодов, ключ подписи сессий и отдельный ключ загрузки редакционных черновиков.

Эти файлы исключены из Git. Не загружай их в GitHub и не публикуй в переписке. Повторный запуск команды не перезаписывает существующий файл. Открытой регистрации пока нет; код действует как пароль и доступен только его владельцу.

## 4. Собери и запусти

```bash
npm run typecheck
npm run build
npm run deploy
npm run secrets:upload
```

Первая команда развёртывания применит SQL-миграции D1 и загрузит приложение. До загрузки секретов вход закрыт. `secrets:upload` установит настройки доступа и активирует новую версию Worker. Команда выведет адрес приложения на `workers.dev`.

Открой адрес, введи код Софьи и проверь урок, карточку, тест и сохранение прогресса после перезагрузки. На другом устройстве используй тот же код. Код администратора открывает редактирование материалов.

При первом входе начальные учебные материалы записываются в D1 без перезаписи существующих правок. Пользовательские результаты в Git не записываются.

## 5. Сохрани конфигурацию в GitHub

После успешного запуска:

```bash
git add wrangler.json
git commit -m "Configure production D1 database"
git push
```

Если Git попросит вход, используй вход в GitHub через установленный менеджер учётных данных или GitHub CLI; пароль сайта GitHub для HTTPS push не подходит. Передавать личный токен в чат не нужно. Также можно изменить только `database_id` прямо в GitHub через кнопку редактирования файла, а затем выполнить `git pull`.

## 6. Подключи обновления из GitHub

Используем GitHub Actions по [CI_CD.md](CI_CD.md). `Check Civilist` проверяет PR и `master`; `Deploy Civilist` доставляет выбранную ветку на QA или проверенный `master` на основной сайт по кнопке `Run workflow`. Это позволяет Дмитрию сначала проверить изменение на QA, затем выпустить его.

Для доставки нужен Cloudflare API-токен в секрете соответствующего GitHub Environment и переменная Account ID. Коды входа Civilist, ключи сессии и редакции уже находятся в Workers и повторно не загружаются при обновлении кода.

Cloudflare Builds — альтернативный способ доставки. Для выбранного процесса он не требуется: настройка второго автоматического выпуска параллельно с GitHub Actions может повторно разворачивать ту же версию или выпускать `master` до ручной команды.

## Что переносится и что ещё требует настройки

- Код интерфейса, начальные уроки, карточки, тесты, игровые дела, практика и шаблоны уже находятся в репозитории.
- Новая D1 первоначально пустая. Начальный контент загрузится автоматически; уже изменённые в старом Sites материалы и сохранённый там прогресс требуют отдельного экспорта и импорта. Не удаляй старый сайт до проверки этих данных.
- Еженедельная подготовка практики на старом Sites привязана к его адресу. Она **не переключается сама**. После запуска нужно заменить адрес и способ авторизации; новый `/api/editorial` принимает `Authorization: Bearer CIVILIST_EDITORIAL_TOKEN` и сохраняет только черновики. На новой платформе нельзя использовать старый флаг анонимной записи.
- Автоматическая AI-проверка свободных ответов и открытая регистрация в этой версии отсутствуют. Свободные ответы сохраняются для самостоятельной сверки с образцом.
- Карточки, тесты, дела, конструктор шаблонов и профиль не требуют платного AI API.

## Локальный запуск для доработок

```bash
npm ci
npm run access:create -- --local
npm run build
npm run db:local
npm run preview
```

Открой http://localhost:8787/login и используй код из `.civilist-access-local.txt`. Локальная база отделена от базы в интернете. Для быстрой разработки интерфейса оставь Worker на порту 8787 и в другом терминале запусти `npm run dev`; Vite проксирует `/api` к локальному Worker.

## Бюджет

Workers Free и D1 Free подходят для начала при соблюдении квот. Это бесплатный тариф с ограничениями, а не обещание неограниченной нагрузки. Не включай Workers Paid, платные AI API и покупку домена для первого запуска. Приложение не использует платные функции.
